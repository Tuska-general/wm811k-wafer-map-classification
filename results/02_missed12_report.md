## 0. 정정: 14장이 아니라 12장이에요

01 결과를 보고할 때 "결함 픽셀이 0개로 잡혀 none으로 예측된 14장"이라고 했는데, 두 가지가 틀렸어요.

- **장수**: 실제로는 불량인데 none으로 예측된 테스트 이미지는 **12장**이에요. 혼동행렬의 none 열을 잘못 셌어요.
- **원인**: 결함 픽셀이 0개라서 none이 된 건 **1장**뿐이에요. 나머지 **11장**은 결함 픽셀이 2~86개 잡혔어요. 그런데 8개 템플릿 중 **none 템플릿과의 상관계수가 가장 높아서** none으로 예측됐어요.

## 3. 노란 픽셀이 정말 없는 걸까, 색이 뭉개진 걸까

결론: **두 가지가 섞여 있어요.** 원인은 두 층이에요.

### 3-1. 흩어진 결함 다이 1칸짜리는 JPEG에서 연한 청록 점으로 바뀌어 "정상"으로 분류돼요 (색 문제)

- 결함 픽셀이 0개인 Center 773253은 웨이퍼 픽셀 중 노란 정도(정상색 0 → 결함색 1) 최댓값이 0.48이에요. 결함색 쪽으로 기운 픽셀(0.25~0.5)이 29개 있지만 모두 경계(0.5)를 넘지 못해 **정상으로 분류**됐어요.- 모의실험: 정상색 바탕에 결함색 점을 찍고 Pillow 기본 설정으로 JPEG로 저장해 봤어요(이 데이터와 같은 품질 75, 색 정보 4:2:0 압축, DATA_SOURCE.md 7-1절).

  | 결함 점 크기 | JPEG 저장 후 결함으로 분류된 칸 | 저장 후 색 예 |
  |---|---|---|
  | 1칸 | **0 / 1** | (124, 230, 208) 연한 청록 |
  | 2×2 | 4 / 4 | (167, 250, 182) |
  | 3×3 | 9 / 9 | (194, 237, 148) |

- 쉽게 말하면 이래요. JPEG는 **밝기는 칸마다 저장**하지만, **색깔은 2×2칸을 묶어 평균 내서 저장**해요. 노란 칸이 하나뿐이면 주변 청록과 색이 섞여서 "밝은 청록"이 돼요. 실제 이미지에 보이는 연한 청록 점과 같은 모양이에요.
- 그래서 **흩어진 결함 다이(1칸짜리)는 대부분 결함으로 잡히지 않고, 2×2 이상 뭉친 결함만 노랗게 남아요.**
- 한계: 실제 이미지가 만들어진 크기 조정 방법은 재현하지 못했어요(DATA_SOURCE.md 7-1절). 그래서 이 실험은 "같은 현상이 생길 수 있다"는 근거이지, 원본과 1:1로 대조한 증명은 아니에요. 원본 WM-811K 맵에서 이 12장의 결함 다이 수를 직접 세면 확정할 수 있어요(아직 안 했어요).

다만 이 현상은 놓친 12장에만 있는 게 아니에요.
- 아래 "비교용 18장"은 맞힌 이미지 전체가 아니라, 같은 유형에서 맞힌 테스트 이미지를 파일 이름 순서로 유형마다 3장씩 고른 거예요.
- 노란 정도 분포를 보면 놓친 12장과 비교용 18장이 0.5 아래에서는 거의 겹쳐요(`02_missed12_yellowness_hist.png`).
- 결함색 쪽으로 기울었지만 정상으로 분류된 픽셀(노란 정도 0.25~0.5)도 놓친 12장은 23~233개, 비교용 18장은 22~157개로 비슷해요.
- **차이는 0.5 위쪽, 즉 진하게 노란 픽셀에서 나요.** 비교용 18장 중 7장은 노란 정도 최댓값이 0.95 이상(최대 1.09)인데, 놓친 12장 중 결함이 잡힌 11장의 최댓값은 0.60~0.93이에요(결함 0개인 773253은 0.48).

→ 이번 표본에서는 **Donut·Edge Ring·Center의 놓친 이미지가 결함 덩어리가 작거나 흐린 편**이에요. 색 뭉개짐이 그 위에서 흩어진 결함을 더 지워요. 다만 표본이 작고(12장 대 18장) 값의 범위가 겹쳐서 경향으로만 봐 주세요. Scratch·Local의 놓친 이미지는 이 설명에 맞지 않아요(2절).

### 3-2. none 템플릿이 "결함 없음"이 아니라 "웨이퍼 좌우 끝에 결함 몇 개"를 배웠어요 (규칙 문제)

- 학습셋 none 70장은 **모두 결함 픽셀이 1개 이상**이에요(중앙값 10개). 그래서 "결함 0개 → none" 규칙으로 none이 된 실제 none 이미지는 하나도 없어요. 테스트셋에서 none을 맞힌 28장도 전부 none 템플릿 상관으로 맞힌 거예요.
- none 템플릿의 결함은 **96%가 웨이퍼 가장자리**(중심에서 12칸 이상)에 있어요. 특히 이미지 **맨 왼쪽·맨 오른쪽 열의 14~17행** 8칸에 몰려 있어요(예: (14,0) 칸은 학습 none 이미지의 80%에서 결함).
- 이 8칸 중 하나라도 결함인 이미지 비율(902장 전체, 테스트셋 포함. 현상 설명용 통계이고 분류 방법에는 쓰지 않았어요)은 none 0.96, random 0.97, near full 0.99, Edge Ring 0.95, Edge Local 0.72, Donut 0.49, Center 0.44, Scratch 0.34, Local 0.25예요.
- **놓친 12장 중 11장**이 이 8칸 중 적어도 하나에 결함이 있어요. 결함 덩어리가 작은 이미지에 이 칸의 결함이 있으면, 전체 모양이 none 템플릿과 가장 비슷해 보이는 거예요.
- 이 8칸의 결함이 원본 웨이퍼에 실제로 있던 불량인지, 이미지로 그리는 과정에서 생긴 것인지는 **확인 필요**예요. 참고로 none 100장은 원본 로트 6개에서만 나왔어요(DATA_SOURCE.md 7-1절). 그래서 이 특징은 "패턴 없음"이라는 유형의 성질이라기보다 **그 로트들의 공통 특징**일 수 있어요(아직 가설이에요). 보류 중인 로트 기준 분할 실험과도 연결되는 부분이에요.

## 4. 고칠 방법 제안 (아직 적용하지 않았어요)

어떤 방법을 쓰든 기준값은 **학습셋에서만** 정해야 해요. 그리고 01과 비교할 수 있도록 별도 스크립트로 만들어야 해요.

### A. 색 분류 개선 (3-1 대응)

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A1. 밝기 기준으로 결함 판정** | RGB 거리 대신 밝기(Y = 0.299R + 0.587G + 0.114B)가 기준값 이상이면 결함으로 봐요. 기준값은 학습셋에서 정해요. | JPEG는 밝기를 칸마다 그대로 저장해서, 색이 뭉개진 1칸짜리 결함도 밝게 남아요. 원인(4:2:0 색 압축)에 맞춘 방법이에요. | 기준값을 하나 더 정해야 해요. 웨이퍼 테두리처럼 밝기가 번지는 곳에서 가짜 결함이 생길 수 있어요. none 이미지의 결함 수도 같이 늘어서 none 구분은 오히려 어려워질 수 있어요. |
| **A2. 4번째 기준색 추가** | 연한 청록 점의 색(예: 약 130, 215, 200)을 "결함" 기준색으로 하나 더 넣어요. 색값은 학습셋에서 정해요. | 지금 방식(가장 가까운 색)을 거의 그대로 유지해서 01과 비교하기 쉬워요. | 연한 청록이 모두 결함이라는 보장이 없어요(원본 대조 전에는 확인 불가). 색값을 고르는 기준이 임의적이에요. |
| **A3. 0/1 대신 연속값 마스크** | 결함 여부를 0/1로 자르지 않고 "노란 정도"(0~1)를 그대로 마스크로 써요. 템플릿과 상관계수도 이 값으로 계산해요. | 버리는 정보가 없어서, 흐린 덩어리도 상관계수에 반영돼요. 기준값이 필요 없어요. | 면적 비율, near full 임계값, 템플릿이 모두 새 정의가 돼요. 그래서 01과 1:1로 비교하기 어려워요. "결함 0개 → none" 규칙도 다시 정의해야 해요. |

### B. none 템플릿 관련 대안 (3-2 대응)

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **B1. none을 템플릿에서 빼고 규칙으로만 판정** | 템플릿은 7개만 쓰고, 면적 비율이 학습셋에서 정한 작은 기준값 이하면 none으로 봐요. | none 템플릿이 다른 유형을 빼앗는 일이 없어져요. | 결함이 적은 Center, Local, Scratch(맞힌 테스트 이미지 중에도 결함 픽셀이 1~16개인 것이 있음. 예: Center 최소 1개, Local 781566 3개)가 오히려 none으로 갈 수 있어요. 지금 none recall 93%가 떨어질 수 있어요. |
| **B2. 좌우 끝 8칸 제외** | 템플릿과 상관계수를 계산할 때 none 템플릿 값이 높은 칸(또는 웨이퍼 맨 가장자리 띠)을 빼요. 뺄 칸은 학습셋에서 정해요. | 로트 특징일 수 있는 칸에 휘둘리지 않게 돼요. | Edge Ring, Edge Local은 가장자리 정보가 중요해서 같이 손해를 볼 수 있어요. 칸을 고르는 기준이 하나 더 생겨요. |
| **B3. 내일 RandomForest 단계에서 다루기** | 규칙은 그대로 두고, 8개 상관계수를 특징으로 넣어 RandomForest가 경계를 배우게 해요. | 따로 규칙을 만들지 않아도 돼요. "none 상관이 근소하게 높음" 같은 경우를 다른 상관계수와 함께 판단할 수 있어요. | 색 문제(3-1)는 그대로 남아요. none 템플릿이 로트 특징을 배운 문제도 특징값 안에 그대로 들어가요. |

## 5. 내일 RandomForest 단계에서 확인할 포인트

같은 분할(test_size=0.3, random_state=42, stratify)을 쓰면 이 12장은 그대로 테스트셋에 들어가요. 그래서 12장이 어떻게 바뀌는지 바로 비교할 수 있어요.

1. **결함 0개 이미지(Center 773253)의 특징값**: 마스크가 전부 0이면 np.corrcoef가 계산되지 않아요(NaN). 8개 상관계수 특징이 모두 NaN이 돼요. RandomForest에 넣기 전에 "규칙으로 먼저 none 처리 / 0으로 채움 / 결측값 그대로" 중 무엇을 할지 정해야 해요. 이 선택이 결과에 영향을 줘요.
2. **근소한 차이로 none이 된 4장**(Edge Ring 766504, Edge Local 810215, Local 791996, Edge Local 810592, 차이 0.01 미만): 8개 상관계수를 함께 보는 RandomForest라면 바로잡힐 가능성이 가장 커요. 몇 장이 바뀌는지 확인해요.
3. **실제 유형과의 상관계수 자체가 낮은 2장**(Scratch 809507 0.048, Local 792182 0.092): 특징에 정보가 거의 없어서 RandomForest로도 못 맞힐 가능성이 커요. 그렇다면 색 개선(A안)이 필요하다는 근거가 돼요.
4. **none 상관이 크게 앞선 2장**(Scratch 801807 차이 0.277, Donut 758427 차이 0.183): none 템플릿 문제(B안)가 RandomForest로 해결되는지 보는 기준이에요.
5. **none 상관계수를 특징에 넣을지**: 넣으면 3-2의 좌우 끝 8칸(로트 특징일 수 있음)이 특징으로 그대로 들어가요. 넣는 경우와 뺀 경우의 결과를 같이 기록해 두면, 나중에 로트 분할 실험에서 비교할 수 있어요.
6. **반대 방향 오류**: none 템플릿 영향이 줄면 실제 none 28장이 다른 유형으로 가는지 확인해요(지금 none은 recall 93%, precision 70%).
